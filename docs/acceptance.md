# 驗收與限制

## 自動整合測試

`npm test` 驗證真實 HTTP／WebSocket 與暫存 SQLite／檔案：

- 按鈴、信令轉送、接聽、三張存檔、掛斷先於模擬 relay。
- 過期 call ID、門口發送開鎖、重複開門不執行。
- 未授權與門口憑證無法讀取主機事件／照片。
- 重複照片與非 JPEG 標頭拒絕。
- 無人回應、通話上限、斷線清理與照片不足記錄。
- 重複角色、錯誤憑證與晚加入主機的預覽要求。

這些測試不證明實體鏡頭、麥克風、網路影音與電鎖可靠度。

## 人工測試（接上設備後逐項記錄）

1. 兩頁連線：按鈴前無鏡頭、無影音連線；門口按鈴後主機看得到現場影像。
2. 尚未接聽時，門口聲音不送出，主機麥克風未啟用；接聽後雙向各說十句確認清楚且沒有回音。
3. 等待至少 3 秒，記錄頁可看見三張不同時點照片，本機 `door_photo` 存在對應 JPEG。
4. 開門後兩邊影音停止、瀏覽器媒體指示燈熄滅；只新增一次 relay 結果，連點不重複開門。
5. 不接聽：30 秒後停止影音、門口顯示自訂聯絡方式，沒有 relay 訊號。
6. 掛斷、關閉分頁、拔網路、Docker 重啟：舊通話結束，不自動開鎖。重啟後事件與照片仍在。
7. 接上真實控制器：設定 3 秒本地脈衝，測試應用當機／斷線後 relay 仍自行復歸；回應遺失記錄未知且不重送。
8. 同時測試門磁與電鎖，確認 relay 接受、鎖釋放、門開／門關是不同事件。
9. 實際門口連續至少 100 次呼叫與 24 小時待命，記錄連線成功率、首畫面時間、聲音中斷、三張照片完整率。

目前自動測試使用模擬 relay，不會操作任何電鎖。照片前三秒擷取由瀏覽器 timer 執行，非即時作業系統保證；背景分頁節流、鏡頭冷啟動、斷線或提前結束都可能影響完整率。
