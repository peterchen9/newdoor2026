# 電腦＋手機測試

電腦跑 Docker、接聽網頁與記錄儲存；Android Chrome 或 iPhone Safari 作為門口端。兩者接在可互通的同一區網，不需要 SIP gateway、不需要月租服務。先使用模擬開鎖，實體電鎖後續獨立接入。

## 1. 啟動區網 HTTPS

PowerShell 在專案目錄執行：

```powershell
./scripts/start-phone.ps1
# 多張網卡時指定電腦實際的區網 IPv4：
# ./scripts/start-phone.ps1 -LanIP 192.168.1.10
```

腳本驗證 IP 屬於本機私有區網，啟動 Caddy 本機憑證 HTTPS，將公開根憑證匯出至 `phone-setup/newdoor-root.crt`，並把網址與憑證 SHA-256 指紋寫入 `phone-setup/connection.txt`。只綁定指定 LAN IP 的 TCP 3443；原有 HTTP 3900 仍只限電腦 localhost。腳本不修改 Windows／手機信任庫，也不修改防火牆。

電腦 IP 改變後重新執行腳本，手機改用新網址。建議路由器為電腦保留 DHCP 位址。Caddy 的 CA 私鑰只在 Docker volume `phone_tls`；不要匯出或分享整個 volume，也不要把 volume 公開到網頁。

## 2. 在兩種手機上安裝本機憑證（各做一次）

把 **只有公開憑證的** `phone-setup/newdoor-root.crt` 透過 USB 檔案傳輸，或你信任的檔案傳送方式送到手機。勿傳 `.env` 或任何私鑰。

這一步會讓手機信任此電腦的本機 CA 簽發的網站，請確認收到的是本專案匯出的檔案，並與電腦 `connection.txt` 的 SHA-256 指紋比對。由使用者親自安裝；不使用「略過不安全網站警告」作為測試方法。

### Android

1. 將 `.crt` 存入手機下載目錄。
2. 「設定 → 安全性與隱私 → 更多安全性設定 → 加密與憑證 → 安裝憑證 → CA 憑證」，選取該檔案；選單名稱因品牌／版本不同，可在設定搜尋「CA 憑證」。依系統提示確認安裝。
3. 使用 Chrome 開啟 `https://<電腦IP>:3443/door`。確認沒有憑證警告後再操作。

### iPhone

1. 開啟收到的 `.crt`，依 iOS 提示下載描述檔；若檔案未觸發安裝，透過支援的檔案開啟方式或 AirDrop 傳入。
2. 「設定 → 一般 → VPN 與裝置管理」選擇剛下載的憑證描述檔並安裝。
3. **再到「設定 → 一般 → 關於本機 → 憑證信任設定」**，對剛安裝的 Caddy 本機根憑證開啟完整信任。僅安裝描述檔尚不足以信任 HTTPS。
4. 使用 Safari 開啟 `https://<電腦IP>:3443/door`，確認沒有憑證警告。

如果是公司管理的手機，系統政策可能禁止安裝使用者 CA；不要關閉裝置管理限制，改用允許測試的手機或由管理員配置受信任憑證。測試結束後可從上述憑證／描述檔位置移除這張本機 CA。

## 3. 電腦與手機配對

### 測試免登入模式

`.env` 設定 `TEST_NO_AUTH=true` 後，重新執行 `./scripts/start-phone.ps1`。電腦 `/host` 與手機 `/door` 開啟即連線，省略下方配對步驟；主機可點「啟用提示音」，手機可直接按鈴，斷線後按「重新連線」。頁面會標示「測試模式 · 免金鑰／免配對碼」。HTTPS 憑證與攝影機／麥克風權限仍需設定。

免登入模式允許任何能連到此服務的裝置使用主機功能及查看事件／照片。測試結束，將 `TEST_NO_AUTH=false` 並重啟，就恢復下方驗證流程。原金鑰保留，不需要重新產生。

### 啟用驗證時

1. 電腦開 `http://localhost:3900/host`，以 `.env` 的 `HOST_TOKEN` 連線。
2. 點「產生手機配對碼」。
3. 手機在 HTTPS 門口頁輸入 6 位數字，點「配對並連線」。
4. 配對碼有效 120 秒、只可兌換一次，猜錯 5 次即失效；全站兌換另限每分鐘 30 次。重新產生碼會使舊碼失效。
5. 手機拿到的憑證只允許門口功能，不可開鎖、讀取照片或產生配對碼；有效 8 小時，僅存在記憶體。頁面重新載入、斷線或換手機時，請重新產生配對碼。

一次只允許一個門口端。測試 Android 與 iPhone 時依序測：前一支先點「斷線」，再讓另一支配對。配對碼、門口憑證、主機金鑰均不記入事件細節或網址。

## 4. 按鈴與通話

1. 手機選擇前鏡頭或後鏡頭。若螢幕上的按鈴按鈕朝向訪客，通常使用**前鏡頭**。
2. 點「保持螢幕開啟」；若瀏覽器不支援或系統拒絕，測試期間手動延長自動鎖定時間。網頁需維持在前景。
3. 點「按鈴呼叫」，第一次允許攝影機與麥克風。此時才啟動鏡頭，麥克風在接聽前停用。
4. 電腦看現場畫面，點「接聽通話」，允許電腦麥克風。若手機顯示「播放對方聲音」，點一下解除瀏覽器自動播放限制。
5. 等待至少 3 秒後，電腦「重新整理」記錄，確認三張照片。
6. 電腦點「開門並結束通話」：兩端媒體釋放，留下模擬繼電器事件，不會真的開門。

手機切到背景、切換 App、鎖屏時，本版主動斷線並釋放影音；返回頁面後需重新配對。這是前景網頁測試端，不是能在背景常駐接聽的手機 App。同房測試時電腦戴耳機，手機與電腦喇叭保持距離。

## 5. 連不上時

- **網頁完全打不開**：確認手機沒有使用行動數據或訪客 Wi-Fi，區網未啟用用戶端隔離；查看 `phone-setup/connection.txt` 網址是否仍正確。
- **Windows 防火牆阻擋**：先確認是你信任的私人網路。可在管理員 PowerShell 執行 `./scripts/enable-phone-firewall.ps1 -LanIP <電腦IP>`，僅允許私人網路的本機子網連入該 IP 的 TCP 3443；腳本不會關閉防火牆或變更網路類型。
- **有憑證警告／沒有攝影機 API**：檢查 CA 信任與網址 IP，勿使用 HTTP 區網網址，也勿略過憑證警告。
- **網頁可連但無影像／聲音**：確認兩端攝影機／麥克風權限、手機維持前景，以及電腦瀏覽器的區域網路／WebRTC 防火牆權限。此版無 TURN，媒體需兩端能直接互通；TCP 3443 通不等於 WebRTC UDP 一定能通。
- **手機配對後顯示角色已連線**：先在原門口端點「斷線」或關閉原頁，死亡連線通常在 10–20 秒內清除。

排查命令：

```powershell
docker compose --env-file .env --env-file .env.phone -f compose.yaml -f compose.phone.yaml ps
docker compose --env-file .env --env-file .env.phone -f compose.yaml -f compose.phone.yaml logs --tail 50 https
```

## 驗證範圍

自動測試覆蓋後端流程、配對有效期、一次性、錯誤次數上限、兌換頻率限制與角色權限。`scripts/check-phone.mjs` 可搭配匯出的根憑證驗證真正的 HTTPS／WSS 代理及配對流程。這些不代表已在實體 Android 或 iPhone 上驗證收音、回音消除、照片完整率或長時間待命；需依 [驗收清單](acceptance.md) 逐支測試並記錄手機型號、OS、瀏覽器版本。

參考：[Caddy 區網憑證](https://caddyserver.com/docs/running)、[Apple 手動憑證信任](https://support.apple.com/en-us/102390)、[Google Android 憑證安裝](https://support.google.com/pixelphone/answer/2844832)。
